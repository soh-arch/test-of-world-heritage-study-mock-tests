# 世界遺産検定3級 模擬試験（非公式）

毎回異なる模擬試験を組み立てる静的Webツール。手書きの問題と、確定した遺産データから
生成した問題を混ぜ、公式の分野比率どおりに20問を出題する。

**https://soh-arch.github.io/test-of-world-heritage-study-mock-tests/**

> 「世界遺産検定」は登録商標（登録第5289275号）です。本ツールは非公式の学習ツールであり、
> NPO法人世界遺産アカデミー、株式会社マイナビおよび世界遺産検定事務局の承認・推奨・監修を
> 受けたものではありません。

## 出題

分野の配分は公式が公表している比率に従う。20問はこの比率で割り切れる。

| 分野 | 公式比率 | 20問での配分 | 問題の出どころ |
| --- | ---: | ---: | --- |
| 基礎知識 | 25% | 5問 | 手書き |
| 日本の遺産 | 30% | 6問 | 手書き＋生成 |
| 世界の自然遺産 | 10% | 2問 | 手書き＋生成 |
| 世界の文化遺産 | 30% | 6問 | 手書き＋生成 |
| その他（時事） | 5% | 1問 | 手書き |

全問に解答してから一括採点し、分野別の内訳と、間違えた問題の解説を表示する。

### 手書き問題（122問）

3級が実際に問うのは、条約や登録手続きといった制度の理解と、遺産ごとの固有の知識
（誰が建てたか、どんな信仰か、何が生息するか）である。これは構造化データからは生成できない。

122問すべてが検証済みで、**121問は一次情報を実際に読んで確認**している
（公式サイト・公式PDF・検定公式データベース pamon・文化庁）。
残る1問は「負の遺産に公式定義がない」ことの根拠がWikipediaしか得られず `secondary` のまま。

### 生成問題（5テンプレート）

| テンプレート | 問い方 |
| --- | --- |
| `year` | 登録年 |
| `place` | 所在都道府県／所在国 |
| `region` | 所在地方／所属地域 |
| `related` | 同じ年に登録された遺産／同じ地方・国にある遺産 |
| `pickByType` | 4件の中から指定された種別の遺産を選ぶ |

配分は `exam-config.json` の出題類型から導出する。コードに書かない。

### 遺産データ（111件）

日本の全27件と、世界の主要遺産84件。

日本の27件は名称・登録年・所在都道府県・種別・登録基準がすべて一次情報で確定している。
世界の84件は、3級の範囲とされる100件のうち公式資料から特定できたもので、
大半は掲載ページからの推定を含む。

『飛鳥・藤原の宮都』は2026年7月登録で、公式テキストの改訂版がまだ出ていない。
公式は『佐渡島の金山』について「改訂版が適用される検定回から出題範囲」と明言した前例があり、
本遺産も同様と推定される。`pendingScope` を付けたうえで**出題には含めている**——
範囲外でも余分に覚えるだけで済むが、範囲内なのに外すと学習の穴になるため。
`src/exam.ts` の `EXCLUDE_PENDING_SCOPE` で切り替えられる。

## 開発

```sh
npm install
npm run dev      # 開発サーバー
npm test         # 出題エンジンのテスト（51件）
npm run check    # データ生成 + 型チェック + テスト
npm run build    # 本番ビルド
```

push すると GitHub Actions が検査して Pages へ配信する。
CI はデータの検証、`build:data` の再生成と差分チェック、型チェック、テスト、ビルドを順に行う。

## 構成

```
data/manual-questions.json      手書き問題（ここを編集して増やす）
docs/research/                  調査記録。facts/ が検証済み、llm-extracted/ が未検証
scripts/build-data.mjs          調査データ → アプリ用データへの正規化と検証
src/generator.ts                問題テンプレート、誤答生成、バリデーション
src/exam.ts                     分野の層化、模試の組み立て、採点
src/main.ts                     画面
```

### データの流れ

```
docs/research/facts/data/*.json  ← 一次情報で確定した調査データ（手で編集しない）
data/manual-questions.json       ← 手書き問題
              │  npm run build:data
              ▼
src/data/*.json                  ← アプリが読む正規化済みデータ（生成物）
```

`build:data` は次を検査し、1つでも失敗すればビルドを止める。

- 都道府県から導出した地方が、調査データの `region_jp` と一致するか
- 遺産IDの重複、両データセットにまたがる重複（ル・コルビュジエ）
- 手書き問題の分野・出典・検証水準・選択肢4つ・正解の所在・解説の有無
- 同じ設問文の問題が2つないか

## 設計の原則

- **正誤判定は必ず `id` で行う。** 遺産名にはダッシュ記号が3種類混在しており、
  表示文字列の比較は当てにならない。
- **属性を問う問題の誤答は、必ず実データから引く。** 年なら別の遺産の実際の登録年、
  都道府県なら同じ地方の別の県。捏造しない。
- **概念を問う手書き問題では、この規則を適用しない。** 公式は「真正性」の誤答に
  似た語感の造語を並べている。実データ由来の規則は属性問題のためのもの。
- **生成した問題は使う前に検証する。** 選択肢の重複、正解と同値の誤答、
  答えが透ける文字数の偏りを弾く。手書き問題も同じ検証を通す。
- **所在地を問えるのは、場所が1つに定まる遺産だけ。** 越境遺産（ル・コルビュジエ）や
  複数地方にまたがる遺産（明治日本の産業革命遺産）は、所在地・関連づけの対象から外す。
- **1回の模試で同じ遺産は1問まで、同じ設問文も1問まで。** 別の問題のヒントになるため。
- **手書き問題には必ず出典を書く。** 事実を誤ったまま学習させるのが最悪の失敗であり、
  検証済みなのに出典のない問題はビルドを通さない。
- **出題比率などの値はコードに埋め込まない。** 公式が非公表の項目は推定値であり、
  `exam-config.json` の差し替えで変えられる状態に保つ。

## 手書き問題を増やすには

`data/manual-questions.json` に追記する。

```json
{
  "id": "basic-icomos",
  "category": "basic",
  "topic": "諮問機関",
  "text": "推薦された文化遺産の専門調査を行い、世界遺産センターに勧告を提出する機関として、正しいものはどれか。",
  "choices": [
    { "key": "a", "label": "ICOMOS（国際記念物遺跡会議）" },
    { "key": "b", "label": "IUCN（国際自然保護連合）" },
    { "key": "c", "label": "ICCROM（文化財保存修復研究国際センター）" },
    { "key": "d", "label": "ICOM（国際博物館会議）" }
  ],
  "answerKey": "a",
  "explanation": "文化遺産の専門調査はICOMOSが行い、4段階の勧告を世界遺産センターに提出する。",
  "source": "3級学習ツール③ 解答（2020.01）",
  "verified": true,
  "verificationLevel": "primary"
}
```

- `category` は `basic` / `japan` / `world_natural` / `world_cultural` / `other`
- 遺産に紐づく問題は `siteId` を付ける（`src/data/sites.json` のIDと一致すること）
- 答えが将来変わる問題は `volatile: true` を付け、設問文に「2026年9月時点で」のように時点を書く
- **`verified: false` の問題はアプリに届かない。** 検証が済んでから真にする
- `verificationLevel` は `primary`（一次情報を読んだ）か `secondary`（それ以外）

## 調査記録

`docs/research/` に、この試験について調べたことを検証の度合いで分けて置いてある。

- `facts/` — 検証済み。一次情報で裏取りしたもの、またはリポジトリ内で再現できるもの
- `llm-extracted/` — LLMが抽出した未検証の情報。実装に取り込む前に裏取りが必要
- `open-questions.md` — 未確認事項のチェックリスト
- `prompts/` — 調査エージェントへの依頼プロンプト

特に、`facts/05-question-type-gap.md` は**公式の出題類型と本ツールの実装の突合表**である。
検定対策ツールである以上、本番との乖離を放置しないため、テンプレートを変えたらここを更新する。

## ライセンスと出典

- 遺産の事実データ（名称・登録年・所在地・登録基準）と、問題の根拠となる事実は、
  公式情報で照合した事実のみ。**解説文などの著作物は一切利用していない。**
- 問題文・選択肢・解説はすべて本ツールが独自に作成したもの。
- UNESCO の公式データは再配布に書面許諾が必要なため、リポジトリに含めていない。
  詳細は `docs/research/facts/exam-spec.md` §2-3。
- 公式が無償公開しているPDF（正誤表、年次の新情報）は、事実の抽出にのみ使い、
  PDF本体も抽出テキストもリポジトリに含めていない。
